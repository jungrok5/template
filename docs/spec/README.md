# 명세 (Spec)

**"이 시스템이 무엇을 · 왜 하는가"의 단일 진실 원천.**
"어떻게 만들었나 · 어떤 함정이 있었나"는 설계 문서(`docs/`)에 쓴다 ([`CLAUDE.md`](../../CLAUDE.md) §2.4).

---

## 항목 형식

각 규칙은 `SPEC-<영역>-<번호>` ID 를 갖고, **구현 파일과 검증 테스트를 명시한다.**

```markdown
### SPEC-AUTH-003 · 세션 만료

무활동 30분이면 세션을 만료시킨다. 만료된 세션의 요청은 401 로 거절한다.

- **상태** — ✅
- **구현** — `src/auth/session.ts`
- **검증** — `expires_session_after_idle_timeout`
```

| 필드 | 규칙 |
|---|---|
| **상태** | `✅` 완료 · `🚧` 진행 중 · `📋` 계획 · `❌` 폐기. **`✅` 인데 검증이 없으면 CI 가 실패한다** |
| **구현** | 저장소 기준 상대 경로. 여러 개면 쉼표로 나열 |
| **검증** | 테스트 이름(함수명 · `it()` 문자열). 저장소 어딘가에 그 문자열이 있어야 한다 |

코드는 같은 ID 를 주석으로 되가리킨다. **주석 문법은 언어에 맞추되 `[SPEC-…]` 형태는 유지한다.**

```ts
// 명세: [SPEC-AUTH-003] 세션 만료
export class SessionPolicy { … }
```

---

## 규칙

1. **명세가 먼저다.** 코드를 먼저 고치고 명세를 나중에 쓰지 않는다. 나중은 오지 않는다.
2. **ID 는 재사용하지 않는다.** 폐기하면 [`retired-ids.json`](./retired-ids.json) 으로 옮긴다.
   이슈 · 회의록에 남은 참조가 조용히 다른 규칙을 가리키면 안 된다.
3. **번호는 영역 안에서만 유일하면 된다.** 영역명은 대문자 + 하이픈 없이 (`AUTH`, `BILLING`, `SYNC`).
4. **한 항목은 한 규칙.** "그리고"로 이어지면 나눈다 — 검증 테스트가 하나로 안 나오면 신호다.

```bash
python3 tools/spec/check_spec_links.py     # CI 가 돌린다
```
